## 1. Project Goal

According to [CLAUDE.md](CLAUDE.md), this is a Bachelor thesis project with the following overall goal:

**Web-based bidirectional transformation and visualization of BPMN process models in RDF/OWL knowledge graphs.**

The finished system should let a user:
1. Upload a BPMN XML file.
2. Visualize the BPMN diagram.
3. Transform BPMN into RDF/OWL.
4. Inspect and query the RDF graph.
5. Transform RDF/OWL back into BPMN XML.
6. Visualize the generated BPMN again.

## 4. Internal Data Model

**Important: there is currently no code for the internal data model.** The file that is supposed to contain it, `src/bpmn_rdf_transformer/model/process.py`, **does not exist yet** — the `model/` folder only has an empty `__init__.py`.

The design *has* been fully worked out and written down in [docs/decisions/0002-internal-model-as-dataclasses.md](docs/decisions/0002-internal-model-as-dataclasses.md), including a complete code sketch. That sketch is a **plan**, not implemented code. It is reproduced and explained here so a future developer/AI knows exactly what is expected to be built next.

### Planned classes (from ADR 0002 — not yet implemented)

```python
@dataclass(frozen=True)
class StartEvent:
    id: str
    name: str | None = None

@dataclass(frozen=True)
class EndEvent:
    id: str
    name: str | None = None

@dataclass(frozen=True)
class Task:
    id: str
    name: str | None = None

@dataclass(frozen=True)
class SequenceFlow:
    id: str
    source_ref: str
    target_ref: str
    name: str | None = None

FlowNode = StartEvent | EndEvent | Task

@dataclass
class Process:
    id: str
    name: str | None = None
    nodes: dict[str, FlowNode] = field(default_factory=dict)
    sequence_flows: list[SequenceFlow] = field(default_factory=list)
```

### Beginner explanation of the concepts used in this plan

- **Class**: a blueprint for creating objects that group related data together. `StartEvent` is a blueprint for "one start event in a BPMN diagram."
- **Dataclass** (`@dataclass`): a Python shortcut that automatically writes the boilerplate code for a class (the constructor, a way to print it, and a way to compare two instances for equality) based on the fields you list.
- **`frozen=True`**: makes objects of that class immutable — once created, their fields cannot be changed. This is planned for `StartEvent`, `EndEvent`, `Task`, and `SequenceFlow`, because each one is fully known the moment it is read from one XML tag.
- **Type hints** (`id: str`, `name: str | None`): tell the reader (and tools like IDEs) what kind of value a field is expected to hold. `str | None` means "either a text value, or nothing at all."
- **Optional value** (`str | None = None`): a field that is allowed to be missing. `name` is optional because a BPMN element does not have to have a human-readable name.
- **`dict[str, FlowNode]`**: a dictionary (lookup table) mapping an element's `id` (text) to the element object itself, planned for quickly finding a node by its id.
- **`list[SequenceFlow]`**: a plain ordered list of `SequenceFlow` objects.
- **Inheritance**: deliberately **not used** in this design. ADR 0002 explains that a shared base class was considered (to avoid repeating `id`/`name` in every class) but was rejected, because it would force awkward workarounds in `SequenceFlow`. Each class is planned to stand on its own.

### Example of how it is meant to be used (once implemented)

```python
start = StartEvent(id="StartEvent_1", name="Start")
task = Task(id="Task_1", name="Do work")
flow = SequenceFlow(id="Flow_1", source_ref="StartEvent_1", target_ref="Task_1")

process = Process(id="Process_1")
process.nodes[start.id] = start
process.nodes[task.id] = task
process.sequence_flows.append(flow)
```

This example is illustrative only — it cannot currently be run, because none of these classes exist in the codebase yet.

## 5. BPMN XML Parser

**Not implemented yet.** `src/bpmn_rdf_transformer/parser/bpmn_parser.py` does not exist. The `parser/` folder only contains an empty `__init__.py`.

The design is documented in [docs/decisions/0004-parser-validation-separation.md](docs/decisions/0004-parser-validation-separation.md). According to that document, the plan is:

- **Supported elements (planned):** `Process`, Start Event, End Event, Task, Sequence Flow — matching the MVP scope in `CLAUDE.md`.
- **Loading XML (planned):** using Python's built-in `xml.etree.ElementTree` (per `CLAUDE.md`'s technology choice; not yet imported anywhere in the code).
- **Namespace handling (planned):** matching elements by the official BPMN namespace URI (`http://www.omg.org/spec/BPMN/20100524/MODEL`) rather than by the literal `bpmn:` prefix text, so the parser is not tied to one specific prefix name.
- **Converting XML to Python objects (planned):** each supported XML element would become one instance of the dataclasses described in Section 4.
- **Unsupported elements (planned):** if the parser meets an element type it doesn't support (e.g. a gateway) inside `<process>`, it is planned to raise `BpmnParseError` immediately ("fail loudly") rather than silently skip it.
- **Exceptions (planned):** `BpmnParseError` for anything that prevents building the model at all (broken XML, missing `id`, unsupported element); `BpmnValidationError` for a model that was built but breaks a BPMN rule (see Section 7). Both classes already exist in `exceptions.py` (Section 3.2), but nothing raises them yet.
- **Fixtures and tests:** none exist yet. `tests/fixtures/valid/` and `tests/fixtures/invalid/` are empty placeholder folders (Section 8).

### Planned parsing flow (not yet implemented)
1. Read a `.bpmn` file or XML string.
2. Parse it into an XML tree using `ElementTree`.
3. Find the `<process>` element using the BPMN namespace.
4. Walk through its child elements; for each supported type, create the matching dataclass object from Section 4.
5. If an unsupported element type is found, raise `BpmnParseError`.
6. Collect everything into one `Process` object.
7. Pass that `Process` object to `validate_process()` (Section 7) before returning it to the caller.

None of these steps currently exist as code.

## 7. Validation Status

**Not implemented yet.** `src/bpmn_rdf_transformer/parser/validation.py` does not exist.

The plan, from [docs/decisions/0004-parser-validation-separation.md](docs/decisions/0004-parser-validation-separation.md), is a function `validate_process(process: Process) -> None` that would check:

| Planned rule | What it would check | Planned error |
|---|---|---|
| Referential integrity | Every `source_ref` / `target_ref` on a `SequenceFlow` must point to an `id` that actually exists among the process's nodes | `BpmnValidationError` |
| No duplicate ids | No two elements (nodes or flows) share the same `id` | `BpmnValidationError` |
| Required attributes | Every element has an `id` | `BpmnParseError` (treated as a parsing problem, since it prevents building the object at all) |

None of these checks exist in code, and there are no tests for them. The ADR also explicitly defers more advanced checks (e.g. "every node is reachable from the start event," "exactly one start event") to a later milestone, to avoid over-building before it's needed.

## 9. Architectural Decisions

Four ADRs exist in `docs/decisions/`. For each: the decision, why it was made, its consequences, its status, and — importantly — **whether the current code actually follows it**.

### [0001 — Use a src-layout Python package with pytest pythonpath configuration](docs/decisions/0001-src-layout-and-pytest-config.md)
- **Decision:** Put the package inside `src/bpmn_rdf_transformer/` and configure pytest with `pythonpath = ["src"]` instead of doing a flat layout or an editable pip install.
- **Reason:** Avoids Python import-path bugs that flat layouts are prone to, without requiring an extra install step.
- **Consequences:** All new code goes under `src/`; no `pip install -e .` needed for now.
- **Status:** Accepted.
- **Followed by code?** **Yes.** `pyproject.toml` and the `src/` folder structure match this decision exactly.

### [0002 — Internal BPMN process model as plain Python dataclasses](docs/decisions/0002-internal-model-as-dataclasses.md)
- **Decision:** Represent each BPMN element type as an independent, flat, frozen dataclass, with no shared base class; `Process` itself stays mutable.
- **Reason:** Dataclasses give free equality comparison; a shared base class would force an awkward workaround for `SequenceFlow`'s extra required fields.
- **Consequences:** Slight field duplication (`id`/`name` repeated across classes) accepted as a low cost.
- **Status:** Accepted.
- **Followed by code?** **Not yet — there is no code to follow it.** `model/process.py` has not been created.

### [0003 — Two-level custom exception hierarchy](docs/decisions/0003-custom-exception-hierarchy.md)
- **Decision:** Use exactly three exception classes — `BpmnError`, `BpmnParseError`, `BpmnValidationError` — instead of a deep hierarchy with one class per specific failure.
- **Reason:** A deeper hierarchy would add classes with no real behavior; message text is precise enough for this project's size.
- **Consequences:** Specific test assertions rely on matching error message text rather than exception subclasses.
- **Status:** Accepted.
- **Followed by code?** **Yes.** `exceptions.py` implements exactly these three classes, matching the ADR precisely.

### [0004 — Separate parsing from validation, and fail loudly on unsupported elements](docs/decisions/0004-parser-validation-separation.md)
- **Decision:** Split parsing (`bpmn_parser.py`) and validation (`validation.py`) into two separate modules/functions; raise `BpmnParseError` immediately for any unsupported BPMN element found inside `<process>`, instead of silently skipping it.
- **Reason:** Keeps two different concerns separate and independently testable; silently dropping unsupported elements risks confusing data loss later during RDF round-tripping.
- **Consequences:** Files using unsupported BPMN elements will currently fail to parse entirely (an accepted, intentional limitation of this milestone).
- **Status:** Accepted.
- **Followed by code?** **Not yet — there is no code to follow it.** Neither `bpmn_parser.py` nor `validation.py` exist.
